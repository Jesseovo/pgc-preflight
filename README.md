# PGC Preflight

超级管理员管理团队、公共资料和全站记录；普通成员使用本地 Agent 审核，Star 成员另有个人创作工作台。Star 可直接在网页使用平台模型创作，游戏制作固定 Opus 5.5；也可独立接入自己的创作 Agent。成员审核仍由自己的 Agent 完成。

- `/admin`：超级管理员后台；授予或撤销 `star`、维护公共词库和规则、管理内容、查看任务和报告。只有管理员可手动上传游戏审核或导入报告。
- `/`：普通成员审核页；`/forge/`：Star 个人创作工作台。成员仅通过自己的 Agent 提交审核；Star 可使用平台创作队列。
- [审核 Agent 接入](docs/agent-integration.md) / [创作 Agent 接入](docs/forge-agent-integration.md)：分别配对，凭据与模型 Key 分离。无需常驻服务。
- 本地审核沿用完整取证、评分、初评和同证据同模型复核，不扣平台模型次数。历史平台模型任务保持来源可识别。
- 创作资料按成员隔离，题材全站原子占用；公共资料由管理员维护，补词须管理员批准。结果保留版本，断线后继续原任务。

## 开发和检查

Node.js 22+；`npm ci` 安装依赖。`npm run build` 运行类型检查、生成两个 Agent 工具及公开说明并构建站点；`npm test` 执行回归。`npm run dev` 是旧轻量前端/浏览器检查调试入口；完整 D1、角色和 Agent 协议使用 `npx wrangler dev` 配合本地迁移运行。

部署前备份数据库，按顺序应用 D1 迁移（新增 `0017_star_agent_workspaces.sql` 和 `0018_review_material_snapshot.sql`），再运行 `npm run deploy`。旧成员 `star=0`；旧创作内容保留为管理员历史档案，旧产物迁移为初始版本，旧外部作品 ID 改为按成员唯一。本地审核首次领取材料时固定规则和校准，初评、复核使用同一份快照。新版本不能在未应用迁移的数据库上运行。

具体业务约定、历史生产证据和发布检查见 [AGENTS.md](AGENTS.md)。本地测试与模拟模型响应不证明真实模型质量、速度或生产上线成功。
