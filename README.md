# PGC Preflight

**上传前，先过一遍。**

一个由视觉大模型审核的单 HTML 游戏基础体检工作台。批量拖入文件，模型查看实际截图、决定基本操作，并给出有证据的检查报告。

网站：**https://pgc.ovoxin.top** · 模型管理：**https://pgc.ovoxin.top/admin**

管理员登录后直接在 `/admin` 使用完整的创作工作台。Forge 的选题台、候选、词库、作品库、样板图、制作简报、审核历史和 AI 模拟审核均以 `C:\Users\Administrator\Desktop\05 Riffle\pgc-forge` 的原始逻辑为准；成员登录后直接在 `/` 使用 AI 模拟审核。

## 怎么用

管理员先在 `/admin` 配置接口地址、模型名称和 API Key，测试图片输入并保存。选题扩写、简报、标签和 AI 模拟审核都统一使用这份配置，Forge 内不再重复配置模型。需要兼容 Chat Completions 且支持图片输入的模型。

组员拖入 `.html` / `.htm` → 独立浏览器运行 → 模型查看截图与日志、操作游戏 → 逐文件输出结果 → 复制或下载报告。

打开主域名时，未登录用户会直接进入成员登录页；管理员登录后进入 `/admin`，成员登录后在 `/` 显示 AI 模拟审核，无需额外访问 `/review`。账号由管理员在 `/admin` 的「成员管理」开通；可单独开关检查权限、停用/恢复账号、重置密码。成员可在审核页修改自己的密码。公开页面不展示后台入口，管理员通过 `/admin` 直接访问。

支持拖到审核页面任意位置，或通过文件选择器一次多选。每批最多 20 个文件，单文件最多 8 MB。画面采集按游戏依次进行，与后台 AI 评分重叠；可选 1–3 路 AI 并发，每个游戏独立显示等待、采集、评分、完成或失败状态，失败可单独重试。模型服务商会收到用于本次审核的游戏源码、截图和运行记录。

已提交后台的任务在关闭页面后继续处理，重新打开可恢复进行中的任务；尚未采集或提交的本地文件需保持页面打开。审核输入短暂存放于 D1 分块表，任务结束后立即删除，异常残留最多保留 24 小时。评分报告和截图沿用 Forge 审核历史，可按游戏查看、复制修改指令、放大截图，或下载 Markdown 报告。

## AI 模拟审核

**游戏检查结论全部由模型给出。** 程序负责上传校验、运行浏览器、记录截图和错误、执行模型的有限操作，以及验证报告结构；模型按原 Forge 的审核标准完成模拟评分。

| AI 模拟审核 | 结果 |
| --- | --- |
| 美学、易玩性、可玩性 | 各 1–3 分，合计 9 分 |
| 原 Forge 平台标准 | 总分 ≥ 7 视为模拟通过，2/2/2 = 6 视为打回 |
| 截图、源码、运行记录 | 每条问题引用证据并生成可复制的修改提示词 |
| 自动体检 | 补充加载、运行时错误、输入、布局和基础流程证据 |

Forge 模拟审核完整沿用 `C:\Users\Administrator\Desktop\05 Riffle\pgc-forge` 的审核逻辑、评分维度、校准样本、雷区和修改提示词。它是 AI 模拟预审，不代替最终人工决定；无法验证的项目需明确说明，动画变化不能直接证明输入有效。未配置模型时不能开始审核，模型接口失败时显示审核未完成。

Forge 审核采集 9:16、9:19.5、9:21 三种竖屏比例的运行记录，以及开局前后画面和脚本模拟输入证据，随后交给模型按原始校准样本评分。HTML 与画面是待审内容，不能修改审核职责。

## 管理页

- 管理密码登录，8 小时会话，HttpOnly Cookie。
- 配置模型接口、模型 ID、启用状态，测试接口与图片输入。
- API Key 使用 AES-GCM 加密后存入 D1；配置读取永不回显密钥。
- 修改接口地址时必须重新填写密钥，避免旧密钥被发送到其他服务商。
- 未使用任何项目内置模型密钥；需要管理员填写自己的配置。
- 成员密码使用 PBKDF2-SHA256 加随机盐保存；账号权限与会话在服务端校验，停用、权限修改和重置密码会撤销旧会话。

## 开发与部署

- `npm run dev`：网站和本地浏览器检查接口，默认 `http://127.0.0.1:8787`。可设置 `PGC_CHROME_PATH`。
- `npm run build`：TypeScript 检查与生产构建。
- `npm test`：上传、网络策略、模型协议、管理登录和密钥存储测试。
- `npm run test:runtime`：真实 Chromium + 脚本化模型响应的集成测试，验证证据/动作/报告链路；不代表真实模型准确率。
- `npx tsx scripts/verify-review.ts`：批量拖放、文件多选、3 路并发、失败重试、新报告和手机布局，以及三种比例真实游戏采集。
- `npx wrangler d1 migrations apply pgc-preflight-db --remote`：初始化设置表。
- `npm run deploy`：Cloudflare Worker、静态资源、Browser Rendering 和自定义域名。

部署需要设置 Worker Secrets：`ADMIN_PASSWORD` 和 `SETTINGS_KEY`。本地同名配置保存在被 Git 忽略的 `.dev.vars`；本地模型设置保存在 `.local-settings.json`。

游戏运行在独立 Chromium 上下文与独立来源，不在工作台页面执行。取证环境只放行常用公共 CDN，阻止其他外部资源、页面跳转和内网请求；资源被环境限制时，模型应明确说明检查条件。Browser Rendering 的并发和每日额度取决于 Cloudflare 当前计划。

`src/` 界面 · `server/checker.ts` 浏览器/模型循环 · `server/model.ts` 审核提示词与协议 · `server/settings.ts` 配置加密与会话 · `server/admin-api.ts` 管理接口 · `server/worker.ts` 线上入口。

选题扩写和制作简报使用 `pgc-forge-jobs` 单并发队列，AI 模拟审核使用独立的 `pgc-review-jobs` 队列，最多 3 个任务并发。部署前需创建这两个队列并应用 D1 migrations；小时定时任务清理过期审核输入。
