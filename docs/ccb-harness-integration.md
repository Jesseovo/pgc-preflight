# PGC CCB Harness 执行适配

本实现保留 PGC 的身份、任务、模型分组、不可覆盖版本及审核协议，增加可关闭的 CCB 执行适配。默认 `wrangler.jsonc` 继续原执行方式；不会因代码合并而自动让成员安装工具、改变 Star 或启用新内核。

## 数据与执行路径

1. 新平台任务在管理员发布验收记录且成员属于灰测范围时，锁定 `harness_policy`。成员自己的 Agent 不进入此路径；已有任务不补写策略。
2. `ForgeRunner` / `ReviewRunner` 仍维护业务检查点。中央 `complete` 入口按任务锁定策略选择原执行器或 `HarnessRunner`，不在失败后换模型或换内核重跑。
3. Harness DO 按全任务占用两个全局名额之一，持久化租约及输入摘要。每个阶段启动独立容器和 CCB 会话。容器只取得任务租约，原模型 Key 留在 Worker。
4. 出站只允许私有 `pgc-harness.internal`。`HarnessOutbound` 绑定确切任务、代次、阶段期限和请求编号前缀；原生消息、工具调用及图片由服务端网关校验并转发，不能通过辅助请求绕过账本。
5. 原始流的终止帧在用量落库后交给 CCB。无法确认用量、截断、异常结束和付费结果未知都停止任务。明确拒绝的有限重试沿用同一请求编号；重复或冲突结果不能付费重放。
6. 最终文件校验哈希后进入原 PGC 校验与版本库。正式报告仍需要同模型、同材料复核。截图、源码或游戏文字没有权限调用平台管理操作。

`0033_harness.sql` 增加任务锁定策略、运行记录、请求账本和事件。`0034_harness_creation_stages.sql` 仅允许新版平台流程保存第二次定向修复；旧成员协议仍只有原先阶段。

## 有界制作和证据

完整制作锁定原策划、样板图、资产及要求清单。阶段会话能够读取并修改自己的 `game.html`，最终保存完整自包含 HTML 和独立 `record.json`。原流程的三种手机比例、四张基础图继续保留。每次修改后的补测校验新文件哈希，旧图不会自动成为新版已修复的证据。

工具返回的补测原图、动作及日志按准确 HTML 哈希编号，随阶段成品原子保存为私有自检证据，不能由模型或成员设备伪造补入。后续制作阶段同时接收四张基础原图和最多十二张补测原图；界面区分本阶段产物与先前、中间版本。自动修复必须引用本阶段交付文件或上一阶段基线的证据，更早或中间版本只提供历史观察。此材料不进入独立正式审核。

游戏预算为 high、每请求最多 64,000 输出 Token、全任务最多 256,000 输出 Token（包含供应商统计的思考）、24 次模型请求及两次定向修复。工具共享六轮、24 个动作、十二张补图和 180 秒额外实际运行预算。工具采集的四图也属于补图与额外运行；浏览器排队、模型等待分别记录。连续轨迹最多 32 点、30 秒。

工具只提供本任务文件读写、精确文本替换及有界浏览器操作。禁止 shell、插件安装、任意文件读取、原生进程创建、任意外联、遥测和公开上传。Node 文件/进程限制、进程内回环网络限制及 Cloudflare 容器外联拦截是不同层的约束；本地进程测试不能代替真实 Cloudflare 隔离验证。

未确认事项保留验证方法；核心玩法变更仍进入原待确认流程。运行上限、失败、缺失证据及未知模型结果不能作为已完成交付。各阶段产物保留，临时 DO 材料最多保留 24 小时，清理成功后才释放执行名额。不保存模型思考正文，不根据历史通过率或关键词调分。

## 发布与验收

研究构建采用固定上游提交与带校验的适配补丁；发布使用镜像摘要。[部署说明](ccb-harness-deployment.md)描述 Linux 构建及关闭态配置。真实供应商兼容、Cloudflare 原生隔离和[六题对照](ccb-harness-evaluation.md)完成前，默认流程继续原样。

验收原始结果、材料、授权依据和分析放在忽略的本地 `artifacts/` 中，不能提交私人游戏或审核意见。测试数量仅说明程序回归，不表示成品更好或审核达到 80% 准确率。尚未执行的验证必须保留为未完成，不能用合成回归填补。
