# PGC 小游戏创作指导 v2

创作指导标识为 `pgc-minigame-v2`。任务应按入队时锁定的指导和输入版本执行；已有任务沿用原格式。这个标识只用于创作，与 Creator Hub 正式审核规则的版本、分数、发布和校准无关。以下说明仓库中的创作约定，不表示已部署或通过真实模型验收。

融合了团队 `pgc-minigame` skill 的选题比较、完整策划、两遍制作与证据驱动的返工。团队 ZIP 的登记脚本、历史 seed、测试作品与真人评语不进入仓库或成员材料；新流程通过本人资料、明确公开的四项摘要和原子机制登记处理选题；旧题材占用仅用于旧协议。

## 选题、策划和样板图

- 选题先构思至少八个方向，比较手势对应的故事动作、规则的新意、相似玩法、失败压力与实现风险，再给至多三个值得做的候选。分不清的地方说明风险，不给预估分数或通过概率。题材是否可占用和玩法是否雷同是两件事。历史偏好和样本分布不能直接决定取舍，选中或进入下一步由用户决定。
- 策划交付完整 F1–F10。明确美术、操作与判定、风险奖励、难度、熟练与新手估算、敌人预警、计分与高潮、玩家可见文案、BGM 和音效。追加稳定编号的制作需求清单，以及带理由的补充决定。修改核心规则、操作、胜负、媒介或音乐风格时标为「核心改动」，交用户确认；数值调整记录前后和原因。
- 样板图单独保存为安全的 9:16 SVG；资产与成品继续使用锁定版本的样板图。资产 HTML 是可预览的另一份交付，含 `<script id="game-assets">`；已有库原样复用，不把审查图复制进游戏，也不把资产审查图当成样板图。
- 管理员自定义模板及参考文字继续保留。新版指导明确区分当前制作要求和旧模板里的历史评分、行数限制与一次性制作建议。

## 制作、精修和自检

平台制作使用 Anthropic 协议的 Claude Opus 5.5，每阶段以自适应思考、`high` 和 32,768 Token 为配置；思考与输出共用该预算。2026-11-05 按用户最新要求，新完整制作默认 `high`，替代原方案的 `low`。成员使用自己的 Agent 和工具时，自选模型、预算与调用安排。均交付可单独打开的 HTML，固定 540×960 逻辑舞台、等比缩放、视口安全区和触摸坐标换算。长屏空余区域由背景延伸，游戏舞台保持完整。禁止外链、网络访问及同源运行。

1. **制作（build）**：读取锁定的完整简报、样板图、资产和用户要求，完整实现游戏循环与已确认的各阶段。返回 HTML、需求实现记录、补充决定及核心改动清单。
2. **采集（capture）**：在受限的独立 Chromium 环境运行该 HTML，取得完整视口图和实际动作、错误等记录。基础采集的四张图覆盖三种手机比例，独立视口不拼成连续试玩。
3. **精修（polish）**：根据采集记录，深化美术、动效、HUD 与声音，保留玩法和资产。对有证据的明显问题做最小修正，输出更新后的 HTML 和自检。之后对新 HTML 重新采集。
4. **定向修复（repair）**：只在有尚未解决、可从新采集复现、且不涉及核心改动的问题时最多执行一次。记录触发、证据、根因、最小改动及需要复测的步骤；修不了或仍无法确认的事项保留待验证。核心改动交成员决定。

自检记录与 HTML 分开，使用 `requirements`、`decisions`、`coreChanges` 和 `selfCheck`，不写进 `pgc:check` 注释。记录区分已确认、体验和待验证；图片与动作引用必须指向本次确实取得的证据。单次触摸不证明完整操作，动画变化不证明输入响应，音频节点不证明听感，截图不证明真机帧率。未执行的重开、后台恢复、完整节奏、挂机打法、试听和真机性能按实标记。两遍制作或有截图均不等于正式审核通过。

## 版本与正式审核

创作版本、输入材料和创作者自检独立保存。成员按 [创作 Agent 接入](forge-agent-integration.md) 执行本人任务，按 [审核 Agent 接入](agent-integration.md) 另外提交准确的 HTML 版本。审核只用独立采集的证据和任务锁定的审核规则，不能读取创作者自评分、自检或同一投稿版本的真人答案来形成审核结论。

实际投稿后的准确作品及版本关联，与 AI 报告、人工终审和广场各自独立。不能用题名、历史分数或作者自述替代准确版本及内容摘要核验。团队 skill 的本地登记、Git 同步、推送和外部投稿不由创作任务自动执行。

## 灰测与管理入口

生产 `CREATIVE_V2_ROLLOUT=pilot` 仅向已登记且启用的灰测成员开放新任务；`all` 明确全量开放，`off` 关闭新入口。开关不改变成员权限、不撤销在途任务，也不影响原流程。`GET /api/forge/state` 与 Agent `context` 返回 `creative_v2_available`。

管理员在「平台设置 → 公共资料 → 创作机制目录与争议复核」发布已脱敏的历史四项摘要或核对成员提供的查重编号。原模型判断保留，管理员语义裁定不可覆盖，精确相同签名不能强行占用。目录变更使旧查重失效，成员重新检查后选择。

制作自检在项目「制作自检」查看，各阶段保留准确文件哈希及四张原始视口图。它不进入正式审核材料；所有修复声明仍与最终输出后的实际采集分开。关键机制改动、延期要求或未解决确认问题保存为待确认产物，不能伪造原输入修订号。

未来评分配对使用审核 CLI 的 `--artifact-version` 和实际投稿后的 `record-submission`。平台有效结论包含组长直接退回，但不会改称管理员终审。现有来源未提供独立文件哈希时，投稿摘要仍是 Agent 声明，不计作已完成严格评估。
