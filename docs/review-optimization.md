# 审核结论、耗时与反馈对照

本轮保持现行规则、评分范围、模型配置和同模型同证据复核。新工具用于减少重复工作、记录事实和验证效果，不提供程序评分兜底。代码测试、合成报告和浏览器协议测试不证明真实审核准确率或时延已达标。

## 执行与计时

需要先应用 `0027_review_timing.sql`。旧任务的开始时间、细分耗时和配置保持未知，不从不断更新的 `updated_at` 倒推。

- 服务端首次领取/开始执行到最终报告保存是执行墙钟，包含正常模型、工具和网络等待。排队时间另报；基础目标180秒，主动选择的增强模式目标300秒，不能事后将慢任务改为增强模式。
- 初评材料首次就绪到初稿保存、复核材料首次就绪到终稿保存，均是服务端观察到的成员阶段墙钟，不能称作纯模型推理时间。重复材料请求、心跳或幂等提交不重置开始时间。
- 成员细分计时强制标记 `member-device`。增强的真实运行、暂停等待为累计时间，不代表一段连续操作。父子跨度不可直接相加。
- 平台传输区分容量、节流、退避、请求及响应时间。非流式 `complete-response` 表示整包到达，不代表首个生成 Token。
- 配置、模式和执行来源分组展示。成员自述的思考强度不是服务端独立证明；未声明保持未知。新声明与初稿原子锁定，不能事后补写或在复核时换强度。
- 计时持久化失败不会重放模型调用或撤回已完成报告。统计中缺少锚点或配置、窗口被截断时不能判达标。

管理员 `GET /api/admin/review-metrics?days=7` 返回分组计时、覆盖缺口和传输统计。按时成功的分母保留已开始的失败、超时及未完成任务。成功子集的P50/P90/P95仅作补充。首批耗时观察每组至少30个已开始任务；最终效果仍需独立评估。

## 减少重复传输与存储

成员新工具明确选择 `materialProtocol: manifest-v1`，原客户端继续获得完整材料。原图和材料按设备、任务、证据摘要隔离；缓存缺失或篡改时重新获取完整材料。复核材料引用同一原图、源码、规则、校准及锁定草稿，不能省略实际读图或将草稿当标准答案。

批量 `review` 提交后先采集第一款并交还 Agent，返回剩余任务和 `continue` 命令。Agent 仍须完成初评、复核和报告读取；工具不会自行运行成员模型。每台设备一次采一款。流水线改善首款等待和吞吐，不等于缩短单款模型判断。

报告成功取得并保存后清理该任务新增私有缓存；未确认完成、断网或保存失败时保留恢复材料。不删除用户原HTML或显式输出。缓存仅按需清理，不新增常驻进程。

平台检查点将不可变材料保存一次，阶段状态引用该材料并保存初稿/终稿，兼容旧检查点。非关键进度写入合并；权限、付费前检查、幂等和关键落库仍等待完成。状态未知的模型请求仍不自动重放。

需要 `0028_creator_feedback_assessment.sql`。管理页新增独立反馈面板，包含同步状态、准确版本关联、AI与平台结论对照、核验声明、文件摘要测量和JSON导出。

仅管理员Cookie可访问，任何设备Authorization请求头仍被拒绝，写入须同源Origin。成员不开放全站研究缓存。以下接口追加在 `/api/admin/creator-feedback` 下：

- `GET /links`：按任务游标分页。
- `GET/POST /assessment`：读取或追加不可覆盖的核验声明。
- `POST /file-evidence`：最多8MiB的管理员文件字节测量，只存摘要与比较结果，不保存HTML。
- `GET /export?jobId=...`：导出单任务对照及来源、核验与缺口。

原 `/link`、`/job` 等保留兼容。管理员填入编号、声明已检查、上传本地同哈希文件，都不能单独证明上游归属或投稿产物。因此本轮这些记录的 `strictEligible` 保持false；成员自动关联不启用。改判、撤销、重开及授权变化按来源状态更新，旧声明不会跨generation复活。原AI报告、成员回填及广场均不改写。

## 结论评估的私有JSON流程

主目标是同一准确投稿版本的AI结论与平台有效通过/退回一致率≥80%，包括组长直接退回。来源明确结论独立于分数；版本状态不能用作品当前状态替代。审核记录按原生ID的最高修订处理，冲突或失效保留未知。

`scripts/review-outcome-eval.ts` 不联网、不调用模型、不下载游戏，也不改来源数据：

```sh
node --import tsx scripts/review-outcome-eval.ts inventory --source PRIVATE_EXPORT --out PRIVATE_NEW_DIRECTORY
node --import tsx scripts/review-outcome-eval.ts freeze --source PRIVATE_EXPORT --registry PRIVATE_REGISTRY --out PRIVATE_NEW_DIRECTORY
node --import tsx scripts/review-outcome-eval.ts evaluate --source PRIVATE_CURRENT_EXPORT --manifest PRIVATE_MANIFEST --predictions PRIVATE_PREDICTIONS --audits PRIVATE_AUDITS --out PRIVATE_NEW_DIRECTORY
```

输出目录0700、JSON0600，拒绝覆盖原文件。registry的cases仅包含 `caseId/workId/versionId/split/executor/mode/modelConfigHash/rulesHash/calibrationHash/inputHash`。摘要为SHA-256。先登记准确输入，后采集；采集失败也不能从登记清单中删除。

freeze返回manifest与摘要。预测和独立审计均须携带同一 `manifestSha256`；预测包含登记后的结束时间、输入/规则/校准摘要及实际锁定证据摘要。已核验审计须引用同一证据。evaluate从原清单枚举案例，缺预测保留missing，并从来源重新取得标签，不能用提交的参考答案覆盖。原文件、规则可比性及盲评资格由独立核验流程提供；本地摘要一致不证明来源真实性或操作员未提前接触答案。

按执行路径、模型配置和模式分别统计。主保留评估每组至少100款独立作品，两类各至少20；同作品不能跨校准、保留及回归集合，主指标每组每作品仅一个预登记版本。既有揭盲样本只作回归。

AI未知、失败和配置不匹配不算一致；缺失结果不得计成功。报告结论一致率、两类召回、混淆矩阵、Wilson区间、多数类基线与质量审计。达到80%样本点估计，不代表总体准确率已有80%的置信保证；多数类基线也不等于模型能力。理由错误、无依据强制整改、关键问题退步和未解释的未知增加保留独立验收约束。

功能部署与效果验收分别记录。缺少准确文件、可信关联、适用规则或独立新样本时，结果保持未验收；不要把新增管理员声明当作补齐这些条件。

## 后续真实投稿灰测

2026-11-04 用户选择先积累灰测成员后续真实投稿，保持只修改 PGC，不追加平台付费回放，也不申请全库文件下载。

- 先固定收集起点与纳入规则，连续保留起点之后的候选任务及失败、未知、未投稿和无法关联状态。旧的23款已揭盲样本仍只用于回归。
- 自然投稿属于前瞻观察，不冒称随机盲测。AI原报告及完成时间必须早于所比较的真人结论；当前投稿答案不得进入该任务AI上下文。
- 作者采纳修改后若文件改变，必须使用修改后准确文件对应的新AI报告。不能把旧版AI报告与新版真人结论拼接，也不能因分数接近按名称猜测关联。
- 后续补齐作品/投稿版本、输入字节与来源文件关系、规则适用关系、模型配置和独立质量核验。管理员声明及本地哈希相等仍不足以证明源站绑定；缺证据保持候选，不计成功。
- 按作品划分校准与保留集合，按执行路径/模型配置/模式分别报告。仅提交并取得真人结论的群体存在投稿选择偏差；同时报告完整候选漏斗，不外推到所有上传游戏。
- 现有 `freeze/evaluate` 命令用于执行前已有准确版本的预登记回放，不能事后补造登记日期来容纳自然投稿。自然任务积累到可核验后，需要独立的前瞻收集记录、原始不可改写报告与来源时间证据，才可计算观察结果；目前尚无合格结果。

本地连续观察由 `readNaturalReviewSnapshot` 和 `scripts/collect-natural-reviews.ts` 提供，不新增线上接口或常驻进程。受控导出函数只读取 PGC 数据库，按固定创建时间起点枚举所有状态及隐藏任务，不以存在报告或已关联为筛选条件。联表键唯一，同一查询给出总数；超过10000条时显式标记不完整。导出保留原AI报告及其存储字符串摘要，省略源码、截图、凭据和个人姓名。

```sh
node --import tsx scripts/collect-natural-reviews.ts --policy PRIVATE_POLICY --snapshot PRIVATE_SNAPSHOT --out NEW_PRIVATE_DIRECTORY
node --import tsx scripts/collect-natural-reviews.ts --policy PRIVATE_POLICY --snapshot NEXT_PRIVATE_SNAPSHOT --previous PRIOR_PRIVATE_DIRECTORY/ledger.json --out NEXT_PRIVATE_DIRECTORY
```

每次生成0700目录及0600的 `ledger.json`、`receipt.json`，拒绝覆盖。后续观察携带上一台账：同一观察幂等，未再出现的任务保留，终态报告、输入和关联变化单独记录；来源撤销可能造成关联不可读，不据此指控篡改。历史与计数摘要用于检查本地意外缺失，不认证上游来源。管理员授权变更后，私有导出仍须按数据使用约定清理，不能用台账绕过来源撤销。

这是按需执行的观察工具，不保证捕获两次导出之间的每个变化。`capturedAt` 固定任务创建窗口上界；查询执行期间的任务进展可能晚于这个上界，保留实际时间，不能把快照当作所有字段在该历史时刻的重建。候选自动合格数始终为0，准确率始终为null；灰测成员资格、按作品去重与分组、原文件绑定、规则及独立质量审计均须在后续评估环节完成。
